# External Model Output Policy

## Status

Canonical documentation policy.

## Purpose

Define how AOIA-Core treats files and artifacts generated by external model sessions, model-assisted reviews, forensic exports, chat-derived reports, and review packets.

## Core Rules

- External-model-output is not canonical source.
- External-model-output is not evidence.
- External-model-output is not provenance.
- External-model-output is not runtime state.
- External-model-output must never be ingested into Evidence Memory by path alone.
- External-model-output must never override docs/ADR/ or docs/governance/ contracts.
- External-model-output may be preserved as historical review context or audit material.
- External-model-output must be clearly separated from active runtime authority surfaces.

## Current Examples

- archive/forensic_exports/reports_forensic_export/
- docs/audit/* external review reports
- model-generated review packets
- Master Library exports
- chat-derived reviewer reports

## Relationship To Evidence

Model consensus is not evidence.
Logs are never evidence.
External model output is operational/review context unless explicitly promoted through future evidence rules with provenance attachment.

## Relationship To GT7

GT7 Batch 3 moved reports/forensic_export/ to archive/forensic_exports/reports_forensic_export/ because it is derived forensic export material and must not remain near live authority surfaces.

## Allowed Use

- reviewer context
- historical analysis
- audit comparison
- human interpretation
- future research archive

## Forbidden Use

- canonical runtime authority
- automatic retrieval authority
- Evidence Memory ingestion
- contradiction entry creation without canonical evidence references
- replacing governance contracts
- replacing ADRs

## Future Work

Before Phase 1A Evidence Memory, implement explicit path-exclusion tests and ingestion guards for external-model-output, generated-runtime, quarantine, and historical artifacts.
