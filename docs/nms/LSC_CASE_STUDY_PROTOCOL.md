# LSC Epistemic-Audit Case Study Protocol

## Role of LSC in AOIA/NMS

The LSC archive is the first epistemic-audit stress-test case study for AOIA/NMS. Its role is to provide complex, high-risk material where models may overinterpret, overvalidate, or collapse uncertainty. The goal is not to prove LSC physics.

LSC is used to test whether AOIA/NMS can prevent premature validation, detect unsupported claims, track provenance, and expose contradictions.

## What LSC Is Used For

LSC is used as a stress-test corpus for:

- claim classification
- provenance tracking
- contradiction exposure
- model behavior comparison
- reviewer workflow design
- boundary testing between evidence, reasoning, and model output

The case study may help show how AOIA/NMS handles difficult epistemic material. It does not make the material scientifically validated.

## What LSC Is Not Used For

LSC is not used to:

- prove neutrino physics
- establish validated physics claims
- turn model output into evidence
- claim AOIA/NMS proves LSC
- merge SCEMDA, HNC, or Gary material into canonical LSC neutrino evidence
- bypass external scientific validation

SCEMDA, HNC, and Gary material may remain external methodological case-study or applied-prototype context, but must not be promoted into canonical LSC evidence through this documentation layer.

## Audit Questions

Reviewers should ask:

- Does the workflow separate evidence from reasoning?
- Does it identify unsupported claims?
- Does it preserve contradictions?
- Does it show provenance gaps clearly?
- Does it prevent model consensus from becoming proof?
- Does it keep LSC framed as a stress-test case study?
- Does it avoid overstating implementation status?

## Evidence Classes

Suggested evidence classes:

- source archive material
- repository governance documents
- provenance records
- contradiction records
- reviewer-approved evidence
- external validation, if independently obtained later

Materials outside these classes should not be treated as evidence without explicit review.

## Model-Output Classes

Suggested model-output classes:

- supported summary
- speculative interpretation
- contradicted claim
- missing-evidence claim
- model-generated only
- needs external validation

Model output remains model output unless separately reviewed and promoted by governance.

## Expected Audit Outputs

Expected documentation outputs:

- claim classification table
- unsupported-claim list
- contradiction summary
- provenance gap summary
- model behavior comparison
- reviewer notes with explicit uncertainty
- recommendations for future harness work

These outputs are audit artifacts. They do not validate LSC physics.

## Prohibited Claims

Do not claim:

- LSC is validated physics
- AOIA/NMS proves LSC
- model agreement validates LSC
- SCEMDA, HNC, or Gary material is canonical LSC neutrino evidence
- the case study is a completed scientific validation
- the system provides production-ready autonomous scientific review

Use language such as "case study", "stress test", "audit material", "unsupported claim", "needs validation", and "review context" where appropriate.
